# spn/access/{token,account} (+ pblind, zona self-hosted) — informe ronda A2

**Archivos** (fork, sin commit; nada tocado fuera de estos 3 dirs):
- `odin/spn/access/token/` (`pm_spn_access_token`): token, errors, registry (Handler = unión cerrada `^PBlind_Handler | ^Scramble_Handler` + procs de despacho), scramble, pblind (handler), request (flujo de 2 vueltas + dump/load de cada mensaje), wire + cbor (códec CBOR propio), **selfhosted** (zonas propias). Tests: token, scramble, pblind, request, selfhosted.
- `odin/spn/access/token/pblind/` (`pm_pblind`): reemplazo de `github.com/rot256/pblind` (pblind, hash, protocol + test).
- `odin/spn/access/account/` (`pm_spn_access_account`): types, view, auth, client (constantes + `client_request`) + test.

**pblind — qué se usó exactamente.** No hay fuente: sin `go/pkg/mod`, sin vendor en el fork, nada descargado. Reconstruido desde el paper (Abe–Okamoto 2000, firmas parcialmente ciegas) sobre P-256 con `core:crypto/_weierstrass` (backend fiat de ecdsa/ecdh: escalares mod n, mult. constant-time con secretos, Shamir vartime sólo para verificar). Sin big-int propio. API = la que usa pblind.go (NewSecretKey, *FromBytes, CompressInfo, CreateSigner/Requester, Message1..3, Check). **Verificado contra Go**: formato de claves (vector privado `HbwGt…` → público `285oM…` = SEC1 comprimido; secreto = big.Int.Bytes) y la clave real de pblind1 parsea. **No verificable** (decisiones propias, documentadas en `hash.odin`/`wire.odin`): hash-to-curve de CompressInfo (SHA-256 try-and-increment), desafío H(α,β,Z,msg) (SHA-512 mod n), nombres de campo/codificación de Message1..3 y Signature (P,W,O,G). ⇒ tokens del pblind1 real de Safing no interoperan; Odin↔Odin completo. El firmante responde una sola vez por estado; el solicitante valida a = rG+cY, b = sG+dZ y c+d = e.

**Formato wire**: texto `zona:base58`, raw `zona:datos`, dsd `'C'`+CBOR con reglas de fxamacker (tags json, omitempty, struct{} = `{}`, `*big.Int` shortest: ≤64 bits entero, si no tag 2). Vectores de bytes armados a mano por esas reglas (scramble storage, PBlindToken, SetupRequest, TokenRequest, nulls en Msgs); el storage scramble además se cruza con `pm:structures/dsd` en ambos sentidos. Vectores Go: scramble SHA2_256 `2VqJ…`→`Cy9tz…`, unittest BLAKE2b `6jFq…`→`ZwoE…`, verificadores fallback1/alpha2 cargan.

**Zona self-hosted** (`selfhosted.odin`): `scramble_generate(n, alg)` → tokens de 32 B + verificadores = base58(lhash(alg,token).Bytes()) (exactamente la clave del mapa de Go; default BLAKE2b_256 como las zonas de Safing, así un hub Go también los aceptaría); config JSON `{zone, algorithm, tokens, verifiers, fallback}` con `make_/parse_/load_/save_scramble_zone_config`, `new_scramble_handler_from_config` (hub = sólo verificadores, cliente = tokens). Test: los tokens generados verifican en un handler con sólo los verificadores (4 algoritmos), archivo hub sin secretos, round trip por archivo. Ojo (igual que Go): scramble = contraseña compartida por zona, GetToken no consume.

**account**: tipos JSON byte-idénticos (round trip del JSON del servidor), may_use, update_view (textos de Go, fallback "Free", prefijo "Portmaster "), headers Device-17/Token-17/Next-Token-17 (+ deprecado) sobre lib/http y lib/httpclient. `client_request` = núcleo sin estado de `access/client.go makeClientRequest` (token, mapeo 401/410/409/423, next token, dsd): URL base siempre parámetro; tests sólo contra lib/http local en puerto efímero.

**Tests** (`odin test odin/spn/access/<pkg> -collection:pm=odin -vet`, 3 corridas, sin leaks): token 19/19 (17–20 s), token/pblind 7/7 (18–24 s; 1000 tokens ≈ 20 s en debug), account 5/5. `odin check -vet -no-entry-point` limpio en los 3 para windows_amd64 y linux_amd64.

**Bugs de Go corregidos**: Scramble ProcessIssuedTokens reemplaza Storage con sólo `verifiersLock.RLock` e IssueTokens lo lee sin lock (carrera; test concurrente) y aliasa el slice; panics por nil en PBlind Verify/Load sin firma, CreateSetup/IssueTokens sin clave privada, ProcessIssuedTokens sin request previo o con mensaje nil; texto de error de IssueTokens con el conteo equivocado. Cambio: SignalShouldRequest se llama fuera de storageLock (en Go, un callback que pida Amount() se bloquea). **Conservado**: shouldRequest `BatchSize/len > 10` (dispara bajo ~9 %, no "≤10 %" como dice el comentario); scramble Load no chequea verificadores.

**Trampas**: (1) `defer` que cambia un resultado nombrado no altera un `return x, y` explícito → `defer if err {sh = nil}` habría devuelto un puntero liberado: limpieza explícita antes de cada return. (2) dsd no sirve para `*big.Int` (rechaza bignum > 64 bits) → códec CBOR mínimo propio sólo para estos tipos. (3) `x_test.odin` con hilos: `context = runtime.default_context()` para no cruzar el tracking allocator. (4) `pt_bytes`/`pt_sec_bytes` reescalan el punto in situ → copiar antes de codificar. (5) El requester toma prestado el token del slice de estados: el slice no debe realocarse mientras viva el estado.
